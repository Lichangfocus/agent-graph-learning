# 在线版第二步：登录 + 进度同步（设计稿，未实现）

> 2026-10-19 · CR-20261019-02 的后续。第一步（GitHub Pages，进度只在浏览器）已上线。

## 目标
focus 在 Mac、手机任一处打开网址并登录后，点亮 / 自测 / 批注会自动同步，并最终落进私有仓库 `Lichangfocus/learn-data` 的 `log/<device>.jsonl`（文件仍是真源）。没登录的访客照旧用 localStorage。

## 方案对比
| 方案 | 登录 | 进度存哪 | 怎么进 learn-data | 成本 | 评价 |
|---|---|---|---|---|---|
| A. GitHub OAuth + Cloudflare Worker（推荐） | GitHub 登录（只允许 Lichangfocus 写） | Worker 收事件，直接用 GitHub App 往 learn-data 追加 `log/web-<设备>.jsonl` 提交 | 实时，就是提交 | Cloudflare Workers 免费档（每天 10 万请求）+ GitHub 免费 → 0 元 | 无数据库，文件即真源，最贴合现有 log 设计；需要一个小后端 |
| B. Supabase（Auth + Postgres） | GitHub / 邮箱登录 | Supabase 表 `events` | box 上的定时任务每天把新事件导出成 jsonl 提交到 learn-data | 免费档（500 MB 库、5 万月活）→ 0 元；闲置 7 天会暂停 | 现成、多人化快（M3 开放时有用）；多一份数据库要对账 |
| C. 纯前端 GitHub 设备码登录 | 浏览器拿 token 直接调 GitHub API | learn-data | 实时 | 0 元 | token 存在浏览器里，手机丢了有风险；不推荐 |

**建议：A**。站点仍在 GitHub Pages；只加一个 Worker（`/api/events`、`/api/me`），与本地 `npm run dev` 的写回接口同形，星图前端只换 endpoint。

## 同步规则
- 事件只追加，带 `id`（uuid）去重；离线时先进 localStorage 队列，联网后补发。
- Worker 端按设备文件追加并 commit（每 30 秒合并一次提交，避免刷 commit）。
- 打开页面时拉取合并后的 log 重新推算点亮状态（沿用 `masteryFromLog`）。
- 隐私：站点和公开仓库都不含个人数据，个人事件只经 Worker 写进私有仓库。

## focus 要亲自做的（转 人生-事务管理）
1. 在 GitHub 建 OAuth App（或 GitHub App，只授权 learn-data），把 Client ID / Secret 发给我（私下发，不进仓库）。
