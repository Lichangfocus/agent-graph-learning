# 产品方向：学者（个人学习 OS）

> v0.2 · 2026-10-07 · 人生-学者 起草，待 focus 确认
> 姊妹篇：[产品方案](product-plan.md) · 决策记录：[ADR-0001 Electron 外壳](adr/0001-electron-shell.md)

## 结论先行

做一个**只为 focus 一个人服务的桌面学习系统**。它持续收集课程和资料，由 agent 在后台研读，再按 focus 的**学习者画像**（我怎样容易理解 + 我已有的通用知识）把任何学科转译成"好视频 + 可交互的网页"。早期 focus 和系统一起调教产品外壳和 agent 内核，直到它成为一位"现成的老师"，focus 只管学。整个系统按一个工程项目来做：有版本，靠真实学习结果来改进。

## 1. 为什么要做

- **时间表很长，靠手工备课撑不住。** 从 2026 Q4 到 2028 Q1，每季一个主题：

    - 2026 Q4：人文艺术
    - 2027：Q1 语言学，Q2 计算机基础（算子 / 硬件 / 昇腾微调），Q3 现代管理，Q4 社会学
    - 2028 Q1：政治经济学
    - 另外每半年一门通识：2027 上半年历史，下半年生物学
  
    节奏是周末、温和的。每个主题都要从零找课、读课、改写，没有引擎就只能浅尝。

- **通用的课和书不是为他写的。** focus 有很强的锚点：AI / agent 系统、产品方法、生产力史、创业。他也有明确的偏好：先框架、按理解依赖排序、原文和白话两层、结论先行、类比要写出失效点。现成的教材用不上这些。
- **"电子书旁边挂一个聊天框"不够。** 今天看到的 Gauth Academy "Infinite Mode"（小红书帖子，下面是转述）指出了方向：一个问题可以成为一门课的起点；课本身是会演示、会模拟、会回应的动态环境。
- **但只有前端是浅的。** 那条帖子下有评论说，不懂教学知识（学习者会卡在哪），前端就只是表面。我们的答案是两层底子：**画像**，加上**提炼过的大学课程材料**。

## 2. 为谁做

**只为 focus 本人。** 先把一个人的学习做到真正好用，不为"潜在用户"做妥协。

- 画像来源：`profile/learner-profile.yaml`（状态 `draft_pending_confirmation`）。
- 将来是否开放给别人，等这个人的闭环成立之后再说。

## 3. 核心洞察

1. **画像是转译层。** 同一份知识，经过"我怎样容易理解 + 我的通用知识"转译后，对 focus 才是好懂的。画像是整个系统的内核，不是一个设置页。
2. **一源多渲染。** 每个单元只有一份规范源 `units/<id>/source.md`，由它渲染出：

    - 网页、视频、单文件预览；
    - 机器可读的导出（JSON / Markdown / `llms.txt`）。
   
    同一份知识用多种形态呈现，人和 AI 都能学。这延续了早先"知识传播"的方向。

3. **教学知识可以积累。** "学习者会卡在哪"不能靠猜，要从真实信号里沉淀，再回写进画像和引擎规则：

    - 选择题错答（干扰项本来就对应常见误解）；
    - 复述；
    - 批注；
    - 问 AI 时问了什么。

4. **交互必须服务理解。** 交互件要参数化（一次只改一个变量，先预测再操作），而且要适合人文学科：

    - 灭点、光与色、裁切构图、墨色浓淡、对比、缩放标注、时间轴。

## 4. 成功是什么样

| 层面 | 成功的样子 | 怎么看出来 |
|---|---|---|
| 学习 | focus 按温和节奏学完每一季，每周末有小产出，季末有一篇综合 | 点亮记录、复述、产出文件（不打分、不显示百分比） |
| 老师 | 从"一起调教"过渡到"只管学" | 每单元需要 focus 动手改的批注越来越少，"要改"类越来越少（目标值待 focus 定） |
| 生产 | 内容生产高效：一个新单元从材料到可学版本主要由 agent 完成 | 每单元的 agent 耗时和 focus 介入次数有记录可比（基线从 U02 开始记录） |
| 传播 | 每个单元同时有视频、交互页和机器可读导出 | `npm run check` 和导出产物齐全 |

## 5. 原则

1. **真实优先。** 结论标注 事实 / 学界共识 / 主流解释 / 有争议 / AI推断。来源只用核实过的（见 `docs/source-registry.md`）。转述明确标"转述，非原文引用"。
2. **source.md 是唯一真源。** 渲染器、导出、视频都从它生成。修订也落回它，不在渲染产物上修。
3. **画像先于内容。** 写作、出题、类比、排序都读画像。可以推广的修订回写到画像和规则，不只修这一个单元。
4. **不造假的掌握度。** 只记"点亮 / 未点亮"和证据（题目全对 + 复述），不显示百分比。
5. **引导而不锁。** 先修关系只给"建议先学"，不硬锁。
6. **本地优先、隐私优先。** 数据持久化在本机，不要账号，不做云同步。
7. **温和节奏。** 一个单元 ≤30 分钟核心内容。错过的周不补，顺延。
8. **按工程来做。** 引擎有版本，每次改进都来自一次真实学习的反馈，并且可验证（`check` / `build` / 截图）。

## 6. 不做什么

- 不做多用户平台、账号、云同步、排行榜或积分。
- 不做"电子书 + 聊天框"。AI 是追问型的助教，只追问不给答案，不是主界面。
- 不做儿童化视觉，不按年龄分级（画像负责转译）。
- 不追求覆盖面。每季只走一条主线，音乐、文学等作为选修。
- 不替代原作和现场。鼓励慢看、看原作。
- 不对外发布有版权风险的图片和视频。对外传播的事等闭环成立以后再议。
